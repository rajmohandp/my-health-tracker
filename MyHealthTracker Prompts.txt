# Incremental Prompts for Health Tracker App

## Prompt 1 — Create the Basic Streamlit App

Build a Python Streamlit application called **My Health Tracker**.

For this first version, focus only on the basic UI structure. Do not add database integration, APIs, AI features, or complex business logic yet.

Requirements:

1. Use Python and Streamlit.
2. Use `uv` for package management and virtual environment setup.
3. Create a clean project folder structure.
4. Create the main Streamlit application.
5. Configure the page with:

   * Page title: `My Health Tracker`
   * Page icon: health-related emoji
   * Wide layout
6. Add a sidebar containing:

   * Application name
   * Short description: `Track your activity, sleep, weight, and overall health trends.`
7. Create the following tabs:

   * Dashboard
   * Activity
   * Sleep
   * Weight
   * AI Health Coach
8. For now, every tab should contain only a heading and short placeholder description.
9. Keep the UI modern, clean, and simple.
10. Do not implement health calculations yet.
11. Provide instructions for:

* Creating the project
* Installing dependencies using `uv`
* Running the Streamlit application locally

12. Explain the purpose of every file created.

Do not build future functionality yet. Stop after the basic application shell is working.

---

* Resting Heart Rate

* Sleep: 6 hr 45 min

`Health Overview`

Add three placeholder charts using sample data:

1. Daily Steps — last 7 days
2. Sleep Duration — last 7 days
3. Weight Trend — last 30 days

Use Plotly for charts.

Requirements:

* Keep the design simple and professional.
* Use responsive Streamlit columns.
* Add proper chart titles and axis labels.
* Do not connect to an external API.
* Do not add database functionality.
* Do not implement AI functionality yet.
* Keep sample data separate from UI code where practical.

Stop after the Dashboard works correctly.

## Prompt 10 — Add AI Health Coach

Implement the **AI Health Coach** tab.

Use Groq for LLM capabilities.

The AI should receive only calculated summaries and aggregated health statistics rather than unnecessarily sending the entire raw dataset.

Allow the user to ask questions such as:

* How was my health this week?
* How does my sleep compare with last month?
* Am I becoming more active?
* What patterns do you notice between activity and sleep?
* Summarize my last 30 days.

The AI response should:

* Focus on trends and wellness observations.
* Avoid diagnosing diseases.
* Avoid prescribing medication.
* Avoid presenting itself as a doctor.
* Clearly distinguish observations from medical advice.

Also generate an automatic:

`Weekly Health Summary`

Keep Groq API keys in environment variables.

Never hardcode API keys.

---

## Prompt 11 — Integrate Fitbit

Replace CSV-only data collection with Fitbit API integration while retaining CSV upload as an optional fallback.

Create a Fitbit integration module.

Retrieve available historical data for:

* Steps
* Distance
* Calories
* Active Minutes
* Sleep
* Resting Heart Rate
* Weight

Requirements:

* Implement Fitbit OAuth authentication securely.
* Keep Fitbit credentials in environment variables.
* Do not hardcode secrets.
* Store tokens securely for local development.
* Handle expired tokens and refresh tokens.
* Normalize Fitbit data into the same internal structure currently used by the application.

Do not rewrite dashboard logic specifically for Fitbit.

The application should consume normalized health data regardless of whether it comes from CSV or Fitbit.

## Prompt 12 — Add Local Database

Introduce SQLite for persistent storage.

Create tables for:

* activity
* sleep
* weight
* heart_rate
* health_goals
* data_sync_history

Requirements:

* Prevent duplicate records.
* Store data by date.
* Support updates from Fitbit.
* Keep database logic separate from Streamlit UI.
* Add functions for inserting, updating, and retrieving health data.

The Streamlit application should retrieve data from the database instead of calling Fitbit for every page refresh.

## Recommended Build Order

Build and test the project in this exact order:

**Prompt 1 → Basic UI**

**Prompt 2 → Dashboard**

**Prompt 3 → Activity**

**Prompt 4 → Sleep**

**Prompt 5 → Weight**

**Prompt 6 → CSV Data**

**Prompt 7 → Date Filters**

**Prompt 8 → Goals**

**Prompt 9 → Analytics**

**Prompt 10 → AI Health Coach**

**Prompt 11 → Fitbit API**

**Prompt 12 → Database**

Do not combine multiple prompts initially. Complete, run, and test each stage before moving to the next prompt.
