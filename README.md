# My Health Tracker

For architecture, data design, operations, troubleshooting, deployment, and
extension guidance, see the
[Project Design & Operations Guide](docs/PROJECT_DESIGN_OPERATIONS_GUIDE.md).

My Health Tracker is a Streamlit application for viewing activity, sleep,
weight, and overall health trends. Users can upload CSV health data from the
sidebar or connect Google Health, with generated sample records retained as a
fallback demo mode. Google Health data takes priority, followed by CSV and then
demo data. Normalized health records, goals, and sync history are persisted in
a local SQLite database. The optional AI Health Coach uses Groq
and sends aggregate statistics rather than raw daily health records.

## Create and run the project

Install [`uv`](https://docs.astral.sh/uv/getting-started/installation/) if it is
not already available, then create a project folder and enter it:

```powershell
mkdir MyHealthTracker
cd MyHealthTracker
uv init --bare
```

Add Streamlit as the application dependency:

```powershell
uv add streamlit
```

For this repository, `pyproject.toml` already declares Streamlit. Install the
locked dependencies and create the local `.venv` with:

```powershell
uv sync --link-mode copy
```

Run the application locally:

```powershell
uv run --link-mode copy streamlit run app.py
```

To enable the AI Health Coach, set the Groq API key in the environment before
starting Streamlit. Never place the key in source code:

```powershell
$env:GROQ_API_KEY="your-groq-api-key"
uv run --link-mode copy streamlit run app.py
```

Alternatively, copy `.env.example` to `.env` and replace the placeholder value.
The application loads this local file at startup; `.env` is excluded from Git.

The app remains usable without this variable; only conversational AI responses
are disabled.

## Google Health setup

Enable the Google Health API and create a Web application OAuth client in
[Google Cloud Console](https://console.cloud.google.com/). Configure its OAuth
redirect URL as `http://localhost:8501` for local development. Add the following
values to `.env`:

```dotenv
GOOGLE_HEALTH_CLIENT_ID=your-google-oauth-client-id
GOOGLE_HEALTH_CLIENT_SECRET=your-google-oauth-client-secret
GOOGLE_HEALTH_REDIRECT_URI=http://localhost:8501
```

The previous `FITBIT_CLIENT_ID`, `FITBIT_CLIENT_SECRET`, and
`FITBIT_REDIRECT_URI` names are temporarily accepted for local migration, but
the Google Health names above are preferred.

Add your Google account as an OAuth test user while the consent screen is in
Testing mode. Restart Streamlit, select **Connect Google Health** in the sidebar,
and approve the requested read-only activity, health-metrics, and sleep scopes.
After the OAuth callback, the app retrieves up to one year of available history.
Use **Sync Health** to refresh the local session data.

OAuth access and refresh tokens are stored in the operating system credential
vault through `keyring`, not in `.env` or the project directory. Expired tokens
are refreshed automatically. **Disconnect** removes the locally stored token;
revoke the application's access from the Google Account permissions page if
consent should also be revoked at Google.

Streamlit will print the local address in the terminal, typically
`http://localhost:8501`.

The `--link-mode copy` option is reliable in OneDrive-backed folders, where
filesystem hardlinks may not be supported. It can be omitted on a normal local
filesystem.

## Local database

SQLite is initialized automatically at `data/my_health_tracker.db`. Override
the location with `HEALTH_DATABASE_PATH`. Google Health syncs and validated CSV
imports use duplicate-safe upserts keyed by date and source. Normal Streamlit
reruns read stored records and do not call Google Health; only OAuth's initial
sync and the explicit **Sync Health** action retrieve remote data. Health goals
and sanitized sync history are also persisted. OAuth tokens remain in the OS
credential vault and are never stored in SQLite.

## File purposes

- `app.py` configures the Streamlit page, sidebar, tabs, Dashboard metric cards,
  CSV upload controls, Activity controls, and Plotly charts.
- `health_data.py` validates uploaded CSV schemas and values, converts dates and
  times, handles duplicate dates, and creates typed records for each tab.
- `date_filters.py` defines the shared historical range options and reusable
  inclusive date-bound and record-filtering functions used across every tab.
- `google_health_integration.py` handles Google OAuth, secure token storage and
  refresh, Google Health API retrieval, and normalization into existing
  application record types.
- `database/connection.py` configures SQLite connections, transactions, WAL,
  foreign keys, and the configurable local database path.
- `database/migrations.py` creates and versions the SQLite schema.
- `database/repository.py` provides duplicate-safe upserts, date-range reads,
  persisted goals, and sync-history operations.
- `services/health_sync_service.py` coordinates Google Health retrieval or CSV
  imports with normalized database persistence.
- `activity_data.py` generates deterministic local activity records and contains
  reusable filtering, averaging, moving-average, metric, and step-goal
  calculations.
- `ai_coach.py` builds aggregate-only health context, creates the automatic
  weekly summary, enforces the wellness safety prompt, and calls Groq.
- `analytics.py` calculates period changes, activity extremes, goal rates, and
  date-aligned Pearson correlations for the Health Insights section.
- `sample_data.py` keeps the Dashboard's hardcoded sample trend data separate
  from its UI code.
- `sleep_data.py` generates local sleep records and provides reusable duration,
  clock-time, rolling-average, metric, and sleep-goal calculations for the Sleep
  tab.
- `weight_data.py` generates 90 days of local weight records and provides
  reusable metric, moving-average, and target-progress calculations.
- `pyproject.toml` defines application and test dependencies managed by `uv`.
- `uv.lock` records exact dependency versions for reproducible installs. It is
  generated or refreshed by `uv sync`.
- `.streamlit/config.toml` supplies the application's clean teal color theme and
  minimal toolbar setting.
- `.gitignore` excludes the virtual environment, Python cache files, local
  secrets, and common editor or operating-system files.
- `.env.example` documents the Groq and Google Health environment variables
  using safe placeholder values.
- `README.md` documents setup, local startup, project layout, and file roles.
